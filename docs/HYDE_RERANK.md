# HyDE 与列表重排序

默认关闭；仅增强每题的首次检索，RAG、Agent 共用。Agent 后续工具补搜继续走原流程。

验证结论以[计分修复版验证摘要](HYDE_RERANK_VALIDATION.md)为准：固定12题，原版与新版完整通过均为7/12；源码覆盖增加，但存在局部新增错误。配对额外耗时中位数7.02秒，包含旧HyDE生成耗时回放。

## 启动和关闭

双击根目录 `start_enhanced.bat`，或在已有 Python/Node 环境中执行：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/start_enhanced.ps1
```

两个开关独立：`-DisableHyDE` 只关闭 HyDE，`-DisableRerank` 只关闭重排；同时传入两个参数恢复原检索。关闭本次服务后，用原 `start_all.bat` 启动，继续使用原配置。启动入口只设置本次进程变量，不写 `.env`。

已有服务可以通过进程环境变量配置：

| 配置项 | 默认值 | 含义 |
| --- | --- | --- |
| `RETRIEVAL_HYDE_ENABLED` | `false` | 一次短假想说明补充语义召回 |
| `RETRIEVAL_RERANK_ENABLED` | `false` | 一轮真实源码候选列表重排 |
| `RETRIEVAL_ENHANCEMENT_SECONDS` | `15` | 增强共享上限，范围 0.1–15 秒 |

Python、Node 可以分别通过已有的 `REPONOESIS_PYTHON`、`REPONOESIS_NODE` 配置。已有端口被占用时，启动器停止，不替换其他服务。

本次本机交付目录另附可双击入口，使用独立数据副本及已验证运行环境；具体位置见本次交付报告。

## 检索与证据

原问题保留关键词和语义检索。融合候选池先保留至多 40 条；HyDE 使用同一生成 Provider 生成最多 600 字符的假想说明，仅对既有 BGE 源码向量做补充查询。按项目、版本、代码块 ID、路径、行范围和哈希去重。

计分修复版按“原检索融合贡献＋一次 HyDE 的 `1/(60+rank)`”排序。HyDE 独有候选没有原检索贡献；其元数据中保存的 HyDE 分数不会再次当作原检索贡献相加。原关键词、语义分数和排名保持不变。

合并后取至多 20 个真实候选供一轮列表重排。重排输入只有原问题和真实源码片段，输出经严格 Schema 校验；ID 必须属于当前候选集合且不能重复。允许完整外层 JSON 代码围栏；有效排序前缀遗漏的真实候选按原顺序补在末尾，并记录补齐数量。空列表、伪造 ID、重复 ID、类型错误会回退。

原关键词、语义、融合分数和融合排名保留，另有 `rerank_rank` 传递增强后的选择顺序，避免证据池按旧融合排名排回去。是否真正经过模型重排，以执行摘要中 `rerank.status` 为准。

最终证据条数与上下文总预算保持原设置。沿用真实源码回读、版本/哈希/行号校验和引用协议；排序首位的非类函数在 200 行、8 KiB 及既有阅读预算内交付完整正文，避免关键尾部分支仅因默认片段截断而丢失。假想说明不进入证据、最终回答提示或引用。

## 时间、取消与记录

HyDE 生成最多 4 秒、补充语义等待最多 2 秒、重排最多 7 秒，同时受共享增强上限、当前工具截止时间和问答工作截止时间约束。增强计入原问答总时限，并保留原最终回答时间。两种短任务均使用 `temperature=0`、关闭 thinking、独立 token 上限，最多一次 HTTP 尝试。最终回答模型与参数不变。

超时、无效返回、无可用向量等情况回退；用户取消继续向上传递。原生向量任务超时后产生的结果不再写入本次证据。

现有回答/历史的执行摘要显示两模块状态、耗时、回退原因及证据选择是否变化。API 元数据还保留候选 ID 和调用用量。`succeeded` 才算增强成功，`fallback` 不算通过。

独立的可选增强桌面试用包默认均为 `true`，不替换旧包或改变普通网页版的默认配置。关闭窗口后，若已有 `user-data/desktop-settings.json`，修改其中的 `hyde_enabled`、`rerank_enabled`；尚未生成个人设置时，修改 `app/desktop-config.json`。设为 `false` 再启动即可关闭，改回 `true` 恢复。个人设置优先于发行默认配置；其他字段尤其 `api_key_dpapi` 保持原样。原密钥加密和进程管理机制保留。

桌面独立源码和试用包仅保留在本机交付目录，不包含在本次主仓库提交中；桌面同步打包不代表桌面源码已提交到GitHub。
