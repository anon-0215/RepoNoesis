# 源鉴 RepoNoesis V3 产品与范围

## 产品定义

- 正式名称：《源鉴（RepoNoesis）——面向真实代码仓库的证据驱动型持续学习智能体》
- 宣传语：“让每一次代码解释，都源于真实源码。”
- 用户：理解陌生 Python 仓库的学习者、课程项目成员、初级开发者和指导者。

核心成果：

> 帮助用户更快理解陌生真实代码仓库、形成可追踪的学习进度，并完成第一次有依据的有效修改；用户能够说明涉及哪些文件、符号和关系，以及判断依据来自哪里。

## 用户问题与定位升级

用户常常不知道从哪里开始、哪些代码支持结论、跨文件流程如何连接，也难记录已理解和仍困惑的内容。GitLearnAgent 重在“给出仓库导读”；RepoNoesis 升级为“在受限预算下收集、校验并组织源码证据，辅助用户持续形成可追踪的仓库理解”。它复用现有 FastAPI、React、SQLite 和静态分析，不整体重写。

## 输入、输出与成功标准

输入包括公开 GitHub URL、自然语言问题、学习目标与反馈，以及程序提取的 revision、文件、符号、代码块和关系。

输出包括带 revision、路径、符号和行号的回答；区分源码事实、静态推断与证据不足的结论；可审计工具轨迹；学习目标、阅读记录、掌握证据、问题和路线；可复现评测报告。

成功标准：

- 路径、行号、哈希和 revision 可程序复核；
- 无有效证据时拒绝确定性回答；
- 冻结集报告 Recall@K、MRR、引用有效率和证据支持率；
- 用户能指出第一次修改涉及的文件、符号、关系和依据；
- 同 revision 未变化代码块复用 Embedding；
- Agent 受步骤、调用、token、时间和结果大小预算约束。

阈值按里程碑冻结，未达标不得宣传“可靠”或“完成”。

## 可验证定义

### 证据驱动

必须同时满足：

1. 结论关联结构化 `Evidence`；
2. Evidence 含 repository/revision、路径、符号、行号、哈希和片段；
3. 输出前校验路径、范围、哈希、片段和 revision；
4. 检索来源及词法、语义、融合分数可追踪；
5. 区分直接事实、静态推断和证据不足；
6. 失效证据标 invalid 并说明原因。

LLM 生成“看似有引用”的文本不满足定义。

### 持续学习

指在 project/repository/revision 下持续保存学习目标，累积已读文件/符号、概念、掌握度证据、未解决问题与路线变化；revision 改变时重验旧证据，并依据已验证行为调整建议。它不指在线训练或微调基础模型权重。

## V3 必做

1. 代码块词法 + BGE-M3 语义 + 融合 + Evidence + 校验 + `/ask`。
2. 检索、源码读取、符号查询和校验的类型化工具层。
3. 有硬预算、超时、取消和审计轨迹的有限 Agent Core。
4. 调用、import/依赖、定义—引用和受限多跳分析。
5. 学习目标、阅读记录、掌握证据、问题和动态路线持久化。
6. 检索、引用、回答、Agent、消融评测及前端证据/降级呈现。

## 非目标与安全边界

- 不训练或微调基础模型；
- 不执行被分析仓库，不安装其依赖；
- 不自动修改、提交或推送目标仓库；
- 不做完整 IDE、完整多语言、云端多用户或大规模分布式索引；
- 不做无限自主 Agent、复杂多智能体、强化学习或图神经网络；
- 不承诺动态符号、运行时行为或未抓取文件的完整理解；
- README、注释、源码字符串均为不可信数据，不能改变权限与工具行为；
- 不在日志、Prompt 轨迹或响应中记录 Key、Token、密码或私钥；
- 无 LLM、无 Embedding、索引损坏或部分失败时展示真实降级状态。

## 禁止夸大

验收前不得声称：理解“整个仓库”；`/ask` 已用语义/混合检索；引用已校验；已支持完整调用图或任意多跳；Agent 能自主开发；路线已长期自适应；能证明运行时行为；系统会训练自身权重。
