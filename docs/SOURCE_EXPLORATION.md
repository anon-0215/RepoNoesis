# 源码探索：报错定位与用例对照

在主项目正常启动、导入或打开已完成分析的项目后，点击左侧「源码探索」。两个入口使用当前选择的项目和版本，不需要启动任何原型服务。

## 报错定位

粘贴普通 Python traceback，或只输入报错文本的最后一行，点击「查找源码候选」。原有消息搜索支持字面量及最多四个格式槽的有限 f-string；每槽最多匹配512字符。结果显示可能的抛错语句、所属函数/类以及真正包围该语句的局部条件和分支。点击「打开抛错源码」进入现有只读源码阅读器，并高亮准确行号。

多个位置均为候选。文本匹配和异常类型名称相同，不证明现场根因、运行时异常类型绑定或完整执行路径。动态消息、任意格式化、复杂异常链/ExceptionGroup完整解析、跨文件根因和数据流不在支持范围。查无结果时不会生成替代答案。

### 普通堆栈关联（2026-10-21）

支持 `File "...", line N, in function` 普通帧、Windows/POSIX路径、相对路径、源码展示行及常见caret提示。调用顺序和递归产生的重复帧保留；默认展开最多三个相关可读位置，其他帧逐项展开。帧与原报错消息候选分开：调用行可以直接阅读，但不会被说成抛错行。经过当前源码范围核对的抛错位置会标明关联帧序号，原消息候选的顺序、数量和分页保留，不因堆栈关联删掉其他可能位置。

只匹配当前workspace/project/revision已保存正文及已取得的同版本材料。粘贴路径只是文本，不据此打开本机文件、下载或执行命令。相对精确路径、至少两个组件的完整仓库相对路径后缀可用于对应；多个可能后缀全部保留，单独文件名即使只有一个候选也视为信息不足，不按函数名消歧。路径包含`..`、控制字符、超长路径或非法行号会拒绝核对。

文件、物理行范围、最内层AST语法范围、提供的源码展示行分别核对。源码或函数信息不一致时仍可打开当前文件原行核查，但不显示其函数/抛错关联，不移动行号找相似语句。定义头、lambda和推导式等无法可靠对应函数范围时保留未知；未提供源码行也明确标记未核对文本。无法解析的文件可在有效行范围继续阅读。**当前快照中有对应位置，不证明用户运行的就是该revision，也不证明现场根因。** 当前材料找不到文件，不能直接断言是外部依赖。

最多4096输入字符、32帧，每帧最多显示5个可能文件并保留匹配总数、源码行预览最多400字符，完整正文使用原阅读器；A整份响应仍有250KB上限。超限粘贴会明确拒收而不是自动截取；帧/候选文件达到上限会说明未处理范围。复杂异常链、ExceptionGroup、压缩递归及未知多行格式显示“未完成堆栈关联”，仅尝试末行消息回退。单行报错继续使用原功能，不以提供堆栈为前提。

该增强无需模型、Embedding、索引迁移或数据库结构变化。普通帧位置/理由由程序静态核对；演示中根据源码构造的堆栈样例必须如此标注，不能称为运行复现或真实故障诊断。

## 用例对照

从已保存的作者测试源码提取简单常量调用、构造器和直接断言，整理可比较的显式输入、共同项、差异和测试预期。默认优先显示代表对照，可搜索、筛选或取消代表筛选后分页查看。选中对照后并排阅读两个场景，通过「查看原始断言」「阅读候选实现」继续阅读真实文件。

这是测试源码中的预期；本功能不执行作者测试。候选实现不等于运行绑定、执行轨迹或因果证明。复杂fixture、动态测试、继承/绑定不明确或外部状态无法解析时会保留限制或明确不支持。自动fixture的存在会显示为部分对照。

## 材料不足

「快照未收录测试」「已收录但解析失败」「没有符合规则的测试」「已提取但没有可配对场景」是不同状态。缺少辅助实现时不会猜测目标，也不会生成假用例。源码探索失败不阻断问答、历史或项目地图。

如果快照缺少tests、conftest或辅助实现，展开「补充同版本源码材料」，填写本地Git仓库目录。程序只从当前完整40位提交身份读取Git文件对象，不读取其他版本的工作树、不联网下载、不执行目标代码或安装其依赖。该版本不在本地时明确拒绝。只有旧的非Git版本标识时不能可靠补充。

补充材料单独保存于配置的 `RUNTIME_DATA_DIR/source-exploration`，与workspace/project/revision绑定，不改写原快照、不增加问答检索池、不重算向量。已保存正文优先；同名内容冲突会拒绝补充。仅允许CRLF/LF传输差异，保留已保存正文及其精确文本哈希，并分别记录Git对象及解码文本哈希。删除本地原始材料目录不会影响已经保存成功的补充材料；数据库与runtime材料应作为同一份私有运行数据维护，它们不放入交付源码包。

「材料范围与诊断」可查看身份、文本SHA-256、文件收录/解析、跳过项、来源和数量限制。内容哈希统一指 `sha256(保存的解码文本.encode('utf-8'))`，不是原始文件字节哈希。保存正文比记录体积短等不确定情况会跳过并记录，不能当作完整文件解析。

已有路径因正文不完整、体积、解码或重复记录而被跳过时，同路径补充内容也不会纳入A/B，以保证候选始终对应现有阅读器实际返回的正文。本轮不修复或覆盖旧快照中的不完整文件；需要由原项目导入/更新流程重新取得可靠快照。

## 有界处理

- 最多500个Python文件、每文件1 MiB、总20 MB；超限文件跳过并记录，不截取正文冒充完整。
- 常量参数化最多128行；最多4000个测试函数、2048个场景尝试、16000项语句工作量；单场景最多64条断言，单项表达式/静态输入/预期最多8192字符。
- 按测试族轮询选取每组最多64个场景，最多3000组对照。达到上限时诊断明确标记，结果不是原仓库的完整测试目录。
- 每页20项，API最多50项；列表只返回摘要，源码经现有接口按需读取。详细结果超过250 KB时拒绝显示并提示继续直接阅读源码。
- 静态候选引用拓展最多两层、16个定义；不存在动态分析或学习提效证明。

## 运行与验收边界

A/B分析本身只用Python标准库AST，不需要LLM或BGE。正常项目首次导入仍沿用原产品本地BGE索引流程，需要预先安装的权重；不会因为使用A/B额外调用生成模型。真实生成问答仍按原有配置工作。

后端新增测试：`python -B -m unittest tests.test_source_exploration tests.test_exploration_error_core tests.test_exploration_test_core tests.test_source_file_api`（在backend目录）。前端使用现有 `npm test` 和 `npm run build`。中性测试夹具由本项目单测生成，不执行第三方源码；A/B核心来自本项目先前验证过的通用原型及最终修复规则，不含固定仓库答案。

本轮真实浏览器验收覆盖Click与HTTPX固定版本的报错候选→源码、对照→断言→实现，且在BGE关闭后完成。真实生成Provider调用为0；问答回归来自确定性和模拟Provider测试。已有全量后端基线问题另见候选报告，不能宣称所有后端测试通过。解压验收复用本机依赖，不代表干净机器部署通过。


## 集成版界面收尾（2026-10-19）

新查询开始会清除上一轮候选、列表和详情；搜索失败后可重试该次已提交查询，编辑框中未提交的草稿不会改变重试或分页。读取单条对照失败时保留当前有效列表，并清除上一条详情；“重试读取对照”重新读取本次选择。

报错定位按“可能位置、所属函数、局部条件、打开源码”排列。用例对照前部展示两侧显式输入与作者测试预期，预期未经执行、部分条件未解析等边界保留在前部。列表的输入差异仅为已有摘要预览，可能截短；完整值、原始断言、候选实现和未确认项可在详情中展开。没有增加匹配、配对或因果判断能力。


## 物理行号与已有数据（2026-10-21）

保存正文、UTF-8内容哈希和仓库版本不变。源码物理行仅由LF、CRLF、CR分隔；VT、FF、U+001C–001E、U+0085、U+2028、U+2029不增加Python AST行号，字符串/注释中的这些字符原样保留。AST、代码块、Evidence、按行读取、全文接口及阅读器使用同一规则。

新代码块提取标识为python_ast_chunks_v1@2；已有旧/未知记录保留旧标识，不在启动时重建索引或历史。普通源码的旧块不受影响；若旧块曾因Unicode分隔而错切，其权威正文切片不匹配会被现有校验拒绝。需要用户另行授权、显式重新分析或更新来修复旧索引；正常版本更新识别新提取标识，不把旧错块冒充新版。A/B直接从对应已保存源码重新静态提取，不依赖旧代码块作为答案。
